# NEXVIRO CODE BATTLE

Платформа соревнований разработчиков: Telegram OIDC → заявка → чек → подтверждение → закрытое задание → бот + ZIP → оценки → рейтинг и призы.

**Начните с [START_HERE_RU.md](START_HERE_RU.md).** Публичный адрес проекта: `https://nexvirobattle.cfd`. Внутренний порт: `17563`.

## Что реализовано

- Telegram Authorization Code Flow с PKCE S256, одноразовым OAuth state, привязкой к браузеру и проверкой подписанного `id_token` по JWKS (RS256, issuer, audience, expiration, issued-at).
- Профиль обновляется при входе. Telegram ID уникален. Числовой `id` и OIDC `sub` обрабатываются как разные идентификаторы.
- Черновики, публикация конкурсов, автоматический старт и окончание, ручной старт, заморозка, возобновление, отмена с причиной.
- Карта и владелец из `.env`, загрузка чеков JPG/JPEG/PNG/WEBP/PDF, проверка через Telegram или сайт. Бесплатные конкурсы тоже поддерживаются.
- Уникальный порядковый номер после одобрения; защита от повторных и конкурентных одобрений. Новая версия отклонённого чека делает старые Telegram-кнопки недействительными.
- Задание не попадает в HTML неавторизованных/неподтверждённых пользователей. Участникам оно открывается после старта.
- Бот, описание и ZIP до 30 MB; GitHub необязателен. Обновление работы до дедлайна, закрытые скачивания владельцем и администратором.
- Пять критериев, несколько судей, средняя оценка и последовательные tie-break правила. Публикация только после завершения и оценки всех работ.
- TOP 3, призы, место/баллы в профиле, комментарии судей для автора, ссылка на получение приза.
- Постоянная очередь Telegram-уведомлений, повторы, журнал ошибок и повторная отправка в админке; аудит действий администраторов.
- Адаптивный тёмный интерфейс на HTML/CSS/Vanilla JS, формы с сообщениями, страницы ошибок, подтверждения опасных действий.
- Alembic, PostgreSQL/Neon, локальные файлы или S3/R2, Docker, systemd и запуск web + bot одним процессом-супервизором.

## Структура

| Папка | Назначение |
|---|---|
| `app/main.py` | Сборка FastAPI, middleware, ошибки, фоновая проверка времени |
| `app/config.py`, `app/db.py` | Настройки, подключение SQLAlchemy |
| `app/models/` | Пользователи, конкурсы, заявки, платежи, работы, оценки, сессии, очередь, аудит |
| `app/schemas/` | Валидация форм и времени Душанбе |
| `app/routers/` | Auth, contests, payments, submissions, leaderboard, admin, files |
| `app/services/` | Правила соревнований, рейтинг, авторизация и хранилище |
| `app/templates/`, `app/static/` | Jinja2, CSS, JavaScript, SVG-значок |
| `bot/` | aiogram 3: команды, проверка чеков, worker уведомлений |
| `alembic/versions/` | Зафиксированная начальная миграция |
| `tests/` | Unit, HTTP integration, безопасность, очередь, PostgreSQL concurrency |
| `deploy/` | Nginx, systemd, Cloudflare Tunnel |
| `scripts/` | Общий запуск и проверка конфигурации |

SQLAlchemy используется синхронно с psycopg. FastAPI исполняет обычные маршруты в пуле потоков; из асинхронных обработчиков тяжёлая работа передаётся в этот пул. Web-процесс запускает небольшой планировщик. Bot-процесс обслуживает Telegram polling и очередь уведомлений. Они используют одну PostgreSQL БД и одно хранилище.

## Требования

Python **3.12+**, PostgreSQL 16/17+, Telegram-бот и его OIDC client credentials, постоянное хранилище, HTTPS для production. Зависимости зафиксированы в `requirements.txt`; `requirements.in` содержит прямые зависимости.

SQLite применяется только для изолированных тестов и локального просмотра. **В production нужен PostgreSQL**, поскольку защита от конкурентных действий использует блокировки строк.

## Локальная установка

Из корня распакованного проекта:

```bash
python -m venv .venv
# Linux / macOS
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Windows PowerShell без изменения ExecutionPolicy:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Не перезаписывайте уже настроенный `.env` при обновлении проекта.

Сгенерируйте свой ключ и вставьте результат в `SECRET_KEY`:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Для локального HTTP укажите `APP_ENV=development`, `APP_URL=http://localhost:17563`. Для реального Telegram-входа настройте разрешённый callback; удобнее использовать собственный HTTPS-адрес через туннель. В приложении нет скрытого тестового входа или встроенного администратора.

## PostgreSQL и Neon

1. Создайте проект/базу в Neon. Скопируйте строку подключения из **Connect** в `DATABASE_URL`.
2. Принимаются `postgresql://...` и `postgresql+psycopg://...`; драйвер выбирается автоматически. Сохраняйте TLS-параметры Neon (`sslmode=require`, `channel_binding=require`, если они выданы).
3. Для миграций предпочтительнее прямой, непулированный endpoint. Это же подключение подходит небольшому приложению; встроенный пул ограничен 5 + 5 соединениями на процесс.
4. Не вставляйте credentials в README, issue, команды публичного лога или Git.
5. Важны резервное копирование/восстановление Neon и отдельная копия файлов чеков/работ. Копия БД без файлов неполна.

Для локального PostgreSQL через Docker заполните `POSTGRES_PASSWORD` в `.env`, затем:

```bash
docker compose -f compose.postgres.yml --env-file .env up -d
```

БД: `nexviro`, пользователь: `nexviro`, адрес с компьютера: `127.0.0.1:5432`. Соберите `DATABASE_URL` со своим паролем (специальные символы должны быть URL-encoded). Из Docker-контейнера `localhost` означает сам контейнер: используйте адрес сервиса/доступный host, а не локальный адрес компьютера.

Добавьте бот в `ADMIN_CHAT_ID` и разрешите отправку документов. Администраторы определяются по **своему user ID**, а не по ID группы и не по username. Первый администратор входит обычным Telegram-входом; если его ID указан в `.env`, появляется Admin. Все администраторы могут управлять конкурсами и оценивать проекты.

## Telegram OIDC / BotFather

Настройка соответствует [официальной документации Telegram](https://core.telegram.org/bots/telegram-login).

1. Создайте своего бота или используйте существующего.
2. В mini app BotFather выберите бота → **Login Widget**. Название настройки относится и к современному OIDC; старый `telegram-widget.js` не используется.
3. Добавьте Allowed URLs: origin `https://nexvirobattle.cfd` и точный redirect URI `https://nexvirobattle.cfd/auth/telegram/callback`.
4. Скопируйте Client ID и Client Secret в `.env`. Оставьте алгоритм подписи **RS256**; приложение намеренно не принимает другие алгоритмы.
5. Вход использует `openid profile telegram:bot_access`. Пользователь должен разрешить сообщения; если нет, он может открыть бота и нажать `/start`.

Callback не зависит от заголовков запроса: он строится из `APP_URL`. У сайта и callback должен совпадать origin, иначе браузер не передаст cookie. Не включайте переписывание callback URL, не добавляйте завершающий slash. Нет отдельного запроса `userinfo`: профиль находится в проверенном ID token. OAuth попытка живёт 10 минут, одноразовая и хранит PKCE verifier на сервере; cookie хранит только привязку браузера.


В другом терминале, в том же окружении и каталоге:


## Raven Host и домен

В [документации Raven Host](https://ravenhost.space/docs/subdomains) app-сервер использует назначенный порт. Проверьте в своей панели, что вашему серверу выделен **17563**. Если порт другой, сначала согласуйте allocation либо используйте фактический порт в командах/прокси.

1. Загрузите весь проект с каталогами `app`, `bot`, `alembic` и скрытыми конфигурационными файлами. В `.env` внесите свои значения; Python должен быть 3.12+.
2. Установите `requirements.txt`, выполните `alembic upgrade head` и `python scripts/check_config.py` в консоли.
3. Для двух отдельных процессов: web-команда выше и `python -m bot.main`. Оба процесса должны видеть одинаковые `.env` и локальные файлы; иначе используйте S3/R2.
4. Если панель предоставляет один запускаемый процесс, стартовая команда: **`python scripts/run_all.py`**. Она запускает web и одного бота, передаёт завершение обоим; если один падает, завершает весь сервис, чтобы панель перезапустила его. Настройте restart on failure. Не запускайте второй polling-бот с тем же токеном.
5. Подключите постоянное хранилище. Не рассчитывайте на временную файловую систему при перезапусках/redeploy.
6. Подключите HTTPS-домен через прокси хостинга либо Cloudflare Tunnel. `APP_URL` должен остаться публичным HTTPS-адресом.

**Одна DNS-запись не перенаправляет 443 на 17563.** Стандартный [Cloudflare proxy не обслуживает произвольный порт 17563](https://developers.cloudflare.com/fundamentals/reference/network-ports/). Нужен HTTPS reverse proxy перед приложением или Cloudflare Tunnel с upstream `http://127.0.0.1:17563`. В `deploy/cloudflared.yml.example` есть конфигурация named tunnel. Запуск cloudflared и возможность фоновых процессов зависят от тарифа/панели; не предполагается, что Raven предоставляет root-доступ.

Если есть собственный сервер с Nginx, используйте `deploy/nginx.conf` после настройки TLS-сертификата. Для Cloudflare → HTTPS origin выбирайте **Full (strict)**. В случае named Tunnel внешний TLS завершается в Cloudflare, соединение туннеля уже защищено.

Установите правила Cloudflare, не кэширующие HTML, `/auth/*`, `/admin/*`, `/profile`, `/payments/*`, `/submissions/*`, `/files/*` и status endpoints. Приложение отправляет `Cache-Control: private, no-store`; не перекрывайте его правилом Cache Everything. Статику кэшировать можно. Rate limiting для авторизации и загрузок лучше дополнительно настроить на edge. Не логируйте query string OAuth callback в прокси.

Не доверяйте произвольному `X-Forwarded-For`. Укажите `--forwarded-allow-ips` только для адреса вашего реального proxy; для локального Nginx/туннеля используется loopback. Не ставьте `*`, если внутренний порт доступен из интернета. Для Docker/systemd приложение привязано к loopback снаружи; для выделенного Raven allocation команда слушает `0.0.0.0` согласно требованию.

## Docker

После заполнения `.env` с Neon URL:

```bash
docker compose build
docker compose run --rm web python -m alembic upgrade head
docker compose run --rm web python scripts/check_config.py
docker compose up -d
docker compose logs --tail=100 web bot
```

На сервере upstream reverse proxy: `127.0.0.1:17563`. Dockerfile исполняет приложение от непривилегированного UID 10001. Web и bot используют общий volume `battle_storage`. Не удаляйте volume без резервной копии. Файл `.env` не включается в образ. Миграции при обновлении запускаются один раз перед перезапуском.

## S3 / Cloudflare R2

Укажите `STORAGE_BACKEND=s3`, приватный `S3_BUCKET`, `S3_ENDPOINT_URL` из панели R2, `S3_REGION=auto`, access key и secret. Для обычного AWS endpoint можно оставить пустым и указать нужный регион. Ключу нужны только действия чтения/записи/удаления объектов выбранного bucket и проверка bucket.

Bucket остаётся приватным. Сайт не возвращает публичные или presigned ссылки; backend проверяет владельца/администратора и отдаёт скачивание вложением. Чеки и ZIP имеют случайные ключи, а исходные имена используются только для отображения. Переключение backend не переносит старые файлы автоматически: сначала скопируйте существующие ключи `receipts/...` и `submissions/...` в новый backend, затем меняйте настройку у web и bot одновременно.

## Правила времени и состояний

- Admin `datetime-local` трактуется как **Asia/Dushanbe**. В PostgreSQL — `TIMESTAMP WITH TIME ZONE`, нормализованный в UTC. UI и письма используют Душанбе.
- `registration_deadline < starts_at < ends_at` проверяется формой и ограничением БД.
- Черновик можно редактировать. После публикации параметры и финансовые условия фиксируются; это исключает незаметную смену условий уже оплатившим участникам.
- Планировщик проверяет время каждые 5 секунд. Маршруты дополнительно проверяют состояние перед чтением/изменением: дедлайн действует и при задержке планировщика.
- Заморозка scheduled сдвигает регистрацию, старт и окончание; заморозка running сдвигает только окончание. Продолжительность паузы вычисляется сервером. При отмене приём закрыт, возвраты выполняет организатор вручную.
- Ранняя команда «Запустить сейчас» закрывает регистрацию немедленно и открывает ТЗ; плановые даты сохраняются, фактический старт записан отдельно.
- Если сервер пропустил и старт, и окончание во время простоя, конкурс становится finished без запоздалого уведомления «старт». Организатору следует иметь мониторинг доступности.
- Заявка без оплаты не резервирует слот. При одобрении действует лимит; если мест не осталось, администратор отклоняет чек с объяснением и решает возврат. Уже отправленные вовремя чеки можно одобрить во время running.
- Оценивание доступно после завершения. Минимум одна оценка на каждую работу; если запланировано несколько судей, дождитесь всех перед публикацией. Публикация необратима через UI.
- Рейтинг: средний total, затем средние functionality, code_quality, stability, originality, затем время отправки **последней версии**. При полном совпадении — ID работы для детерминированности.
- В рейтинг входят только отправленные и оценённые работы. Несдавшие проект видят, что место им не присвоено.

## Уведомления и эксплуатация

Уведомления записываются в БД в одной транзакции с изменением состояния. Отправка не блокирует публикацию результатов и не откатывает подтверждение оплаты. Worker захватывает запись с lease, использует `SKIP LOCKED`, повторяет временные ошибки до 12 раз с задержкой, учитывает Telegram RetryAfter. TelegramForbidden/BadRequest требуют исправления настройки или открытия бота пользователем; повтор можно запустить из Admin → Журнал и уведомления.

Доставка имеет семантику **at least once**: если Telegram принял сообщение, а процесс остановился до фиксации этого факта в БД, возможен повтор. Денежные решения и номера участников при этом не дублируются. Telegram callback содержит версию чека; проверка прав и актуальности повторяется сервером. «Другое» использует временное состояние ввода; после перезапуска бота просто выберите причину заново.

Данные платежа являются подтверждением организатора, а не банковской автоматической сверкой. Бот показывает чек администратору; перед одобрением проверяйте реальное поступление денег. Проект не списывает деньги с карт и не выплачивает призы автоматически.

## Безопасность

- Сессия: подписанная `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS; непрозрачный токен с серверным сроком жизни. Logout отзывает запись сессии.
- Все изменяющие формы требуют CSRF и проверяют Origin при наличии. Admin-права проверяются на backend. Скачивания доступны только владельцу/админу.
- Jinja autoescape, текстовые ТЗ/комментарии, CSP без inline JS, запрет фреймов, nosniff. Секреты не помещаются в JS/HTML, exception messages не выводятся пользователю.
- SQLAlchemy параметризует запросы. Contest row lock сериализует изменение участия, платежей, работ, оценок и публикацию; БД обеспечивает уникальность.
- Размер HTTP body ограничен до разбора multipart. Проверяются формат, MIME, расширение, ZIP paths/symlinks/CRC/размер распаковки/коэффициент сжатия. ZIP не извлекается в файловую систему.
- Загруженный исходный код остаётся недоверенным: сервер его не исполняет. Архивный валидатор не является антивирусом; администратор проверяет проекты в изолированной среде.
- TLS, резервные копии, лимиты/мониторинг хоста и безопасное хранение `.env` остаются частью настройки развёртывания. Не включайте debug в production.

Обычный `pytest` создаёт временную SQLite БД и применяет настоящую миграцию Alembic. Production `.env`/данные не используются. Для PostgreSQL предоставьте отдельную **тестовую БД с именем `nexviro_test`** в `TEST_DATABASE_URL`, затем выполните `pytest -q`. Её таблицы очищаются между тестами. Никогда не указывайте рабочую БД.

GitHub Actions `.github/workflows/test.yml` поднимает отдельный PostgreSQL 17 и запускает тесты, включая одновременные одобрения и гонку за последний слот. Учётные данные в workflow — только одноразового CI-сервиса; реальных секретов в проекте нет.

Проверяются OAuth подпись/claims/state/PKCE/replay, время, lifecycle, ranking/tie-break, диапазоны оценок, HTTP-сценарий двух участников, блокировка результатов и изменений, CSRF, admin access, XSS, IDOR, проверки файлов и очередь уведомлений. Внешние Telegram/OIDC вызовы в автоматических тестах заменены контролируемым тестовым транспортом: реальные пользователи и реальные деньги не затрагиваются.

Подробности выполненной проверки и ограничения окружения — [VERIFICATION.md](VERIFICATION.md).

## Обновление

1. Сохраните резервную копию БД и хранилища.
2. Обновите код и зависимости, сохранив `.env` и пользовательские файлы.
3. Выполните `alembic upgrade head`, затем `python scripts/check_config.py`.
4. Перезапустите web и один bot; проверьте `/healthz`, вход и очередь уведомлений.

Умышленно отсутствуют seed-пользователи, тестовые конкурсы и обход входа в рабочем приложении. Первый конкурс создаёт администратор через сайт.
